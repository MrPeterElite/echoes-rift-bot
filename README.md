# ECHOES OF THE RIFT — HP, еда и медицина (health-1)

Накопительный патч: включает предыдущие исправления стабильности.
Устанавливается поверх проекта из присланного архива или поверх stability-1.

## Что работает

- У каждого персонажа 100/100 HP и 0/0 брони по умолчанию. Состояние
  хранится в отдельной таблице SQLite; существующие записи не сбрасываются.
- В ЛС: «❤️ Состояние» или /состояние. В своей RP-локации: /дуель.
  /дуель только показывает карточку; не вызывает противника и не начинает бой.
- /предмет НОМЕР показывает описание предмета из инвентаря.
- Магазин и инвентарь показывают эффекты из тех же настроек, которые
  используются при применении. Цена медкомплекта — 400 CR.
- Еда даёт временные HP на 30 минут: лапша 5, сухпаёк 8, орехи 10,
  батончик 12, обед 15, сэндвич 18, фрукты 22, мясной набор 30.
  Бонусы не складываются. Более сильный заменяет слабый с подтверждением;
  равный/слабый не расходуется и не обновляет таймер. Еда не лечит ранения.
- Бинт лечит 10 HP, гемостатик 20 HP. Общий предел — 20 HP на эпизод
  ранения, включая сцену и помощь после неё. Он сбрасывается после полного
  восстановления вне боевой сцены. Открытие карточки и рестарт не сбрасывают лимит.
- Медкомплект лечит до 50 HP; в сцене — один на получателя, независимо
  от лимита бинтов/гемостатиков. Вне сцены можно использовать повторно,
  пока здоровье не восстановлено. При 0 HP обычное лечение недоступно.
- При частичном лечении бот показывает фактический эффект и кнопки
  подтверждения/отмены. Подтверждение действует 60 секунд и привязано к
  пользователю, чату, персонажу, предмету и состоянию. Старые кнопки
  не подтверждают новую операцию. При рестарте подтверждение отменяется.
- Списание одной порции и изменение здоровья выполняются одной транзакцией.
  При полном здоровье, исчерпанном лимите или запрете предмет не расходуется.
- Вода, кофе, энергетик, чай, алкоголь и остальные медикаменты пока
  имеют только RP-эффект. Это указано в карточках. «Феникс» не объявляет
  автоматическое воскрешение: исход определяет ведущий.
- При подтверждённом удалении персонажа его здоровье удаляется вместе
  с остальным состоянием; баланс возвращается к 1500 CR, как согласовано.

## Боевые сцены: временное ручное управление

Полноценного боя ещё нет: атаки, поглощение урона бронёй, списание временных
HP от попаданий, раунды, лечение союзника и автоматический расход действия
не реализованы. Броня пока хранится и отображается; её формулу не выбирали.
Сейчас предметы применяются только к своему персонажу.

Чтобы ограничения можно было использовать и проверить уже сейчас,
добавлены служебные команды. Работают только в административном чате
для owner/senior/admin, изменения пишутся в журнал:

/здоровье ID HP               — задать основное HP от 0 до 100
/броня ID ТЕКУЩЕЕ МАКСИМУМ    — задать показатели брони
/сценастарт ID [ID ...]       — отметить участников одной боевой сцены
/сценаконец ID               — завершить сцену ВСЕХ участников сцены этого ID

Это отметки состояния для ведущего, а не приглашения на дуэль.
Используйте их после согласования сцены с игроками. Участник с 0 HP
или участник уже активной сцены не может быть добавлен повторно.

Если сцена отмечена до истечения 30 минут после еды, бонус закрепляется
до конца сцены. Еду внутри сцены применить нельзя. При завершении сцены
остаток еды сгорает. Лимит медкомплекта обновляется при новой сцене;
лимит простой первой помощи сохраняется, если персонаж ещё ранен.
Ведущий учитывает основное действие лечения вручную.

## Проверки и установка

INSTALL_HEALTH.txt — установка, ручная проверка, откат.
python -m unittest discover -s tests -v

Пройдены 44 локальных теста (18 новых + 26 предыдущих), проверка маршрутов
команд VKBottle и статический анализ. Протестирована миграция копии
присланной SQLite: все старые строки сохранены, integrity_check = ok,
повторная миграция успешна, резервная копия соответствует исходной базе.
Среда: Python 3.12, Windows, vkbottle 4.10.0, aiosqlite 0.22.1.
Реальная доставка кнопок/сообщений в VK и запуск на BotHost не проверялись.

Перед первой миграцией health-1 создаётся копия в backups рядом с БД.
Путь выбирается как раньше: DATABASE_PATH, DB_PATH, DATA_DIR/database.db,
существующая /app/data/database.db, затем database.db проекта.
Запускайте один экземпляр бота. Резервная копия при миграции не заменяет
регулярное резервное копирование работающей игры.
